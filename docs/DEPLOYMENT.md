# Deployment

This project is deployed as:
- Static frontend generated by Nuxt (SSG: every page is real HTML).
- PHP API for forms and CRM integration (`api.racklog.cl`).

CI (`.github/workflows/ci.yml`) generates the site, audits dependencies and
tests the API on every push to `main`. Deploy only a commit with green CI.

## Before deploying (one time, in this order)
1. **GTM**: change the conversion triggers (GA4 and Google Ads) from the
   custom event `purchase` to `generate_lead`. The forms no longer send
   `purchase`; if this is skipped, Ads conversions stop being counted.
   Also check that GA4 page views use the "History Change" trigger and
   that Clarity is not also loaded from inside the GTM container.
2. **Kommo token**: `api/config/token.php` on the server must contain the
   current token (or set `KOMMO_BEARER_TOKEN` in the hosting panel).
3. **Sketchfab**: revoke the old API token in the Sketchfab account. The
   site no longer uses it (public search needs no token).
4. **Legal texts**: fill the placeholders in `pages/politica-privacidad.vue`
   and `pages/terminos.vue` (`[RUT]`, hosting provider, retention periods,
   whether prices include VAT) and have them reviewed by a lawyer.

## Frontend deployment (static)
1) Generate the site

```bash
npm ci
npm run generate
```

2) Upload the **contents** of `.output/public` to the web root (e.g.
   `public_html/`), including the hidden `.htaccess` file. It replaces the
   previous rule that answered every URL with `index.html` (soft-404).

3) Delete files from previous deploys that no longer exist (old
   `_nuxt/*.js`, `quote/`, `accesorios/`) or upload to an empty folder.

## API deployment (PHP)
1) Upload the `api/` folder to `api.racklog.cl` (PHP 8.0+, `mail()` enabled).
2) Keep the existing `api/config/token.php` on the server (gitignored).
   If missing, copy `api/config/token.example.php` and fill the token.
   Same for `api/config/supabase.php` (intranet leads, see `docs/ENVIRONMENT.md`).
3) `api/.htaccess` blocks `config/`, `utils/`, `partials/`, `endpoints/`
   and `storage/` from the web and forces HTTPS.
4) Optional: `APP_ENV=development` enables CORS for `http://localhost:3000`.
   Never set it in production.

## Post-deploy checks
- `curl -I https://racklog.cl/` → 200, `strict-transport-security` present.
- `curl -I https://www.racklog.cl/` → 301 to `https://racklog.cl/`.
- `curl -I https://racklog.cl/no-existe` → **404**.
- `https://api.racklog.cl/api/health` → `{"status":"ok"}`.
- `curl -s -X OPTIONS -H "Origin: https://evil.example" https://api.racklog.cl/api/send-email -D -`
  → no `access-control-allow-origin` header.
- Submit a contact form and a quote: internal email, client confirmation
  and Kommo lead are created; GTM Preview shows `generate_lead`.
- Open the browser console on the home page: no Content-Security-Policy
  report-only warnings. After a week without warnings, rename the header
  in `public/.htaccess` from `Content-Security-Policy-Report-Only` to
  `Content-Security-Policy` to enforce it.
- Submit `https://racklog.cl/sitemap.xml` in Google Search Console.

## Operations
- **Uptime**: create monitors (e.g. UptimeRobot, free) for
  `https://racklog.cl/` and `https://api.racklog.cl/api/health` (expects
  200 and `"status":"ok"`), with email/WhatsApp alerts.
- **Error tracking**: recommended Sentry (free tier) for frontend errors;
  it needs an account and DSN. API errors are logged as one JSON line per
  event (`form_submission`, `uncaught_exception`) with `request_id`, which
  the API also returns in the `X-Request-Id` header.
- **Backups**: the site is fully rebuildable from git (RPO for code: last
  commit). Leads live in Kommo and in the `contacto@racklog.cl` mailbox;
  check that the hosting keeps daily backups of the mailbox and of
  `api/config/token.php`. Target: RTO 4 h (redeploy from git), RPO 24 h.
- **Lost leads**: if Kommo fails, the lead still arrives by internal email
  and the log line has `"lead_created":false` with the reference.
